# 단계별 개발 로드맵

## 0단계: 데이터 확보 가능성 검증

산출물은 데이터 카탈로그, 실제 컬럼 매핑, 라이선스, 기간·결측·스키마 변경 조사다. 따릉이 이력과 대여소를 우선하고 날씨, 행정경계, 지하철을 순차 검증한다. 행사는 독립적인 go/no-go 판단을 한다.

종료 기준:

- 예측 target과 station-hour 집계가 실제 필드로 가능하다.
- 대여소 위치와 ID 변경 정책을 설명할 수 있다.
- 시간대, CRS, 결합 키, 재배포 조건을 기록했다.

## 1단계: SQL/GIS와 EDA

PostgreSQL/PostGIS의 최소 raw, staging, mart 구조를 만들고 품질검사, 시간 집계, 행정구역 결합, 대여소·지하철 거리 분석을 수행한다. QGIS로 이상 좌표와 공간결합을 검토한다.

종료 기준:

- mart.station_hour의 grain과 중복 규칙이 테스트된다.
- 결측 시간, 잘못된 좌표, 대여소 변경 이력이 리포트된다.
- 수요의 시간·요일·계절·지역 패턴을 설명할 수 있다.

## 2단계: Baseline

지속성, 학습기간 평균, 전일 동일 시간, 전주 동일 시간 예측을 구현한다. 시간순 분할과 rolling-origin 평가를 먼저 고정한다.

종료 기준:

- 테스트 구간이 잠겨 있다.
- MAE/RMSE와 지역·대여소 slice가 재현된다.
- 모든 후속 모델이 동일 평가 계약을 사용한다.

## 3단계: 기본 머신러닝

Random Forest와 LightGBM으로 Model A와 B를 비교한다. 전처리는 학습기간에만 fit하고 실제 미래 관측 날씨를 사용하지 않는다.

종료 기준:

- 베이스라인 대비 개선폭을 제시한다.
- 과적합과 feature importance의 한계를 설명한다.
- 날씨·공휴일 추가의 효과를 동일 fold에서 비교한다.

## 4단계: GIS·행사 외부 변수

거리, 주변 시설, 행정구역 등 공간 특징을 추가한다. 행사 데이터는 시간·장소·취소·변경 이력과 당시 가용성을 확인한 경우에만 Model C에 포함한다.

종료 기준:

- 모든 거리 연산의 CRS가 명시된다.
- 행사일·비행사일 표본 수와 오차를 함께 보고한다.
- Model C가 불가능한 경우 그 이유와 대체 분석을 기록한다.

## 5단계: 딥러닝

PyTorch LSTM으로 과거 수요 시퀀스를 학습하고 같은 테스트 구간에서 LightGBM과 비교한다. 복잡성 자체를 성과로 간주하지 않는다.

종료 기준:

- seed, 시퀀스 길이, early stopping, 학습 곡선이 기록된다.
- 성능, 학습비용, 추론비용을 함께 비교한다.

## 6단계: 평가와 포트폴리오 결과

전체, 시간대, 지역, 대여소, 행사일, cold-start별 MAE/RMSE와 실패 사례를 정리한다. forecast-validation 스킬로 최종 검증한다.

## 7단계: API·대시보드

FastAPI로 배치 예측을 조회하고 Streamlit에서 지도·차트로 표현한다. 단순 지도 표시가 아니라 실제 공간 집계와 오차 분석 결과를 보여준다.

## 8단계: Docker·공개 준비

데이터와 비밀정보를 제외한 재현 환경을 정리하고 README에 결과 이미지, 데이터 계보, 실행 방법, 한계와 향후 과제를 추가한다.
