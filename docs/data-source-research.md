# 데이터 출처 조사 계획

## 상태 표기

- 미검증: 사용자 계획 또는 조사 후보이며 공식 자료를 아직 확인하지 않음
- 확인: 공식 페이지와 데이터 사전에서 제공 여부를 확인함
- 샘플 검증: 실제 파일의 필드·타입·결측·범위를 확인함
- 계약 확정: 코드와 테스트에 사용할 스키마를 고정함

현재 아래 데이터는 모두 **미검증** 상태다. 구체적인 실제 컬럼명이나 URL을 사실로 간주하지 않는다.

## 조사 절차

1. 서울시 또는 해당 운영기관 공식 페이지에서 데이터명, 제공 방식, 갱신 주기, 과거 보존 범위를 확인한다.
2. 데이터 사전과 샘플을 확보한 뒤 필수 의미 필드가 실제로 존재하는지 검사한다.
3. 라이선스, 출처 표기, 재배포, 상업적 포트폴리오 공개 조건을 기록한다.
4. 파일별 조회일, 기준일, 크기, 인코딩, 체크섬을 카탈로그에 기록한다.
5. 시간대, 결측, 중복, 식별자 타입, 좌표 범위, CRS를 표본 검사한다.
6. 월별·연도별 스키마 변경과 대여소 ID 변경을 조사한다.
7. 검증된 실제 컬럼만 src/spatial_demand/data/contracts.py와 테스트로 승격한다.

## 행사 데이터 go/no-go 기준

다음 조건을 모두 충족해야 Model C의 예측 입력 후보가 된다.

- 테스트 기간을 포함한 충분한 과거 자료가 있다.
- 행사 시작·종료와 장소를 대여소에 시공간 결합할 수 있다.
- 취소, 연기, 장소 변경 이력을 구분할 수 있다.
- 예측 발행 시점에 알려졌던 행사 정보 또는 당시 snapshot을 재구성할 수 있다.
- 공개·재배포 조건이 포트폴리오 사용과 양립한다.

조건을 충족하지 않으면 행사를 Model C에서 제외한다. 사후 확정 관객수는 인과 설명이나 사후 분석에는 사용할 수 있지만 예측 입력으로 사용하지 않는다.

## 날씨 가용성 원칙

- 과거 실측 날씨를 EDA와 사후 상한선 분석에 사용할 수 있다.
- 운영 예측 성능에는 예측 발행 시점에 실제 이용 가능했던 과거 예보 snapshot이 가장 적절하다.
- 과거 예보를 확보하지 못하면 날씨를 제외하거나 학습기간에서만 계산한 기후 평균을 사용한다.
- 실측 미래 날씨를 사용한 결과는 oracle/upper-bound로 분리하고 주 성능으로 보고하지 않는다.
