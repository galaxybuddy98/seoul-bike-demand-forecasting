# 아키텍처

## 시스템 경계

첫 버전은 서울시 따릉이의 대여소별 시간당 대여건수를 배치 방식으로 예측한다. 온라인 학습, 실시간 재배치, 모바일 앱은 범위 밖이다.

    공식 원천
      -> 원본 보존 및 품질검사
      -> Pandas/GeoPandas 정제
      -> PostgreSQL/PostGIS
           raw -> staging -> mart.station_hour
      -> 특징 데이터셋
      -> Baseline / Random Forest / LightGBM / LSTM
      -> 평가·예측 결과 테이블
      -> FastAPI
      -> Streamlit 지도와 비교 차트

QGIS는 좌표·공간결합 품질검사와 정적 포트폴리오 지도 제작에 사용한다.

## 데이터 계층

| 계층 | 책임 |
|------|------|
| raw | 원천 값, 출처, 조회일, 기준일, 체크섬 보존 |
| staging | 타입, 시간대, 식별자, 좌표계 정규화와 품질 플래그 |
| mart | 대여소×시간 수요, 대여소 이력, 행정구역, 외부 변수, 예측 결과 |

원천 파일을 직접 수정하지 않는다. 실제 스키마는 샘플과 데이터 사전 검증 후 DDL로 확정한다.

## 분석 단위와 시간

- 기본 grain은 station_id × hour다.
- 주 target은 시간당 대여 시작 건수다.
- 서울 지역 시간대를 명시하고 저장·집계 규칙을 고정한다.
- 대여소 이전·신설·폐쇄는 가능하면 유효기간이 있는 이력 차원으로 처리한다.
- 예측 horizon은 데이터 검증 후 정하되 모든 특징에 availability timestamp를 둔다.

## GIS 연산

- 대여소 점과 행정구역 polygon의 공간 결합
- 대여소와 지하철역 간 최근접 거리
- 반경 내 지하철역·주요시설 수와 유형
- 행사 시간 범위와 행사장 buffer를 이용한 주변 대여소 연결
- 행정구역별 실제·예측 수요 집계
- 지역별 잔차 지도와 오차 공간 패턴 분석

저장용 geometry는 출처 CRS를 보존하고 통합 좌표는 원칙적으로 EPSG:4326을 사용한다. 거리와 buffer는 서울에 적합한 지역 투영 CRS를 공식 메타데이터 확인 후 선택한다. 경계선 위 점의 포함 규칙과 잘못된 좌표 처리도 SQL 테스트로 고정한다.

## 모델 계층

- Model A: 시간, 요일, 계절, 과거 수요
- Model B: Model A + 예측 시점에 이용 가능한 기상·공휴일
- Model C: Model B + 공간 특징 + 검증된 행사 특징

같은 평가행, 시간 분할, metric으로 비교한다. Model C는 행사 데이터의 과거 snapshot 또는 당시 가용성을 증명할 수 없으면 만들지 않는다.

## 서비스 경계

첫 서비스는 사전 계산 예측을 읽는다. FastAPI는 상태, 대여소, 모델 버전, 시간 범위별 예측 조회만 제공한다. Streamlit은 지역·시간·모델 필터, 지도, 실제값 대 예측값, 오차 분석을 표현한다.

## 확장 조건

재고, 반납, 용량, 재배치 이력이 공식 자료로 확보되고 시점별 가용성을 확인한 경우에만 재고 예측과 운영 최적화로 확장한다.
